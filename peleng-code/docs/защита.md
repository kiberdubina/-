# Защита: мультикамерный 3D-трекинг

## Что сделано

Один конвейер на файл, пять роликов Way1 и телефоны: кадр → детектор пятна → 2D-трек(и) → триангуляция лучей → фильтр Калмана → поле 3D и прогноз. След на экране растёт только из измерений, не из таблицы цели. Таблица `SM_AA_track` нужна для погрешности.

## Методы

- Детекция: вычитание фона / цвет / режимы пятна (профиль в `config.yaml`).
- 2D: Калман на плоскости, ворота к прогнозу; несколько треков — чужое пятно не перехватывает главный.
- 3D: `triangulatePoints` по парам, отсев по репроекции; дальность от ближайшей камеры.
- Сглаживание: Калман 6D (XYZ + скорость), горизонт `predict_s`.
- Пропуск: трек не обнуляется сразу, на поле остаётся прогноз.
- Поза cam-5 обновляется по номеру кадра (камера крутится).

## Что отвергли на первом проходе

- Тяжёлые готовые стеки (DeepStream, MVTracker, нейросети на каждый кадр) — сначала простая воспроизводимая цепочка на OpenCV.
- aniposelib / JAX — отложено из‑за веса зависимостей.
- Рисование эталонной траектории из CSV — не соответствует ТЗ (координаты должны считаться по картинкам).

## Как добавить камеру

Тот же `Session.add_source` / меню «Добавить видео» / телефон по кабелю. Нужна поза в `session.poses` (лист ChArUco или таблица Way1). Алгоритм fuse не меняется: чем больше лучей с измерением, тем лучше пара/набор для XYZ.

## Ступени ухудшения условий

0. Одна цель, камеры стоят, позы известны.  
1. Помеха на кадре (второе движение) — multi 2D/3D.  
2. Короткий пропуск на части камер — прогноз и след.  
3. Крутящаяся камера — поза по кадру.  
4. Телефоны, рассинхрон — тот же шаг сессии, точка при ≥2 камерах.

## Фишки, которые сохраняем

Телефоны по кабелю, поле 3D со следом и конусами камер, прогноз траектории.
