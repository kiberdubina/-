# Защита: мультикамерный 3D-трекинг

## Что сделано

Два режима на одних модулях:

- **Точка** (мяч, дрон, телефоны): кадр → детектор пятна → 2D-трек(и) → триангуляция лучей → Калман 6D → поле 3D и прогноз.
- **Наземная машина** (фура Way1, профиль `way1` с блоком `vehicle`): кадр → фон → пятна → подгонка **3D-ящика** к рамкам всех камер сразу → фильтр с моделью движения автомобиля → 3D-ящик на видео и в поле 3D.

Координаты считаются только по картинкам. Таблица `object_transform_SM_AA_track` используется для оценки погрешности, причём сравнение идёт **по номеру кадра**.

## Результат на Way1 (5 камер, 1001 кадр)

Контрольный прогон: `python run_control.py` или меню «Файл → Контрольный прогон Way1…», около 4 минут.

| | До | Сейчас |
|---|---|---|
| Кадров с 3D | 9 % | **100 %** |
| RMSE | 32 м (Калман) | **2,9 м** |
| Медиана ошибки | — | **1,5 м** |
| 95 % кадров точнее | — | **6,4 м** |
| Максимум | 75 м | **8,4 м** |

По участкам: там, где фуру видят ≥ 2 камеры, ошибка **0,7–1,3 м**. Хуже всего три места: 200–299 (фуру видит одна cam-2, ~4,6 м), 600–799 (холм, деревья закрывают cam-3 и cam-4, ~3,3 м), 0–99 (старт с места, ~2,2 м). Всё по кадрам: `reports/way1_control/metrics_by_segment.csv`, `trajectory.csv`, `error_t.png`.

Что выдаёт прогон: видео каждой камеры с каркасом 3D-ящика (`control_cam-N.mp4`), мозаику всех камер с XYZ, курсом, тангажом и скоростью (`control_all.mp4`), рамки силуэтов и проекции ящика по кадрам (`boxes2d.csv`), графики XYZ(t) рядом с эталоном (`xyz_t.png`), план XY (`plan_xy.png`) и отчёт `metrics.txt`.

## Метод (режим машины)

1. **Модель цели — 3D-ящик относительно задней оси.** Габарит 19,7 × 5,1 × 6,4 м. Опорная точка (pivot меша, её и даёт таблица) стоит на 15,4 м впереди задней оси и на 3,0 м выше земли, то есть перед кабиной, а не в центре фуры. Если сравнивать с таблицей центр силуэта, ошибка 8–10 м заложена ещё до любой детекции. Габарит и pivot найдены один раз подгонкой ящика к силуэтам камер 1–4 (≈ 500 рамок, МНК с робастной функцией). Это свойства 3D-модели фуры, их лучше уточнить у организаторов.
2. **Состояние:** x, y, z задней оси, курс ψ, тангаж θ, скорость v, скорость поворота ω. Задняя ось выбрана потому, что у машины без бокового скольжения скорость задней оси направлена строго вдоль корпуса. Перед в повороте заносит наружу на atan(d/R), и подгонка подтвердила это: модель «перед тянет заднюю ось по трактрисе» объясняет силуэты лучше касательной (медианная невязка 10,5 → 7,6 px).
3. **Движение:** CTRV с уклоном. По плану — дуга со скоростью v·cosθ, по высоте — v·sinθ. Тангаж следует процессу Орнштейна–Уленбека (дороги в среднем горизонтальны, σ ≈ 7°, τ = 3 с).
4. **Измерение:** рамка силуэта в каждой камере. Прогноз — рамка оболочки восьми углов ящика, **обрезанная кадром**. Стороны, упёртые в край кадра, ничего не измеряют. Окклюзия только уменьшает силуэт, поэтому отклонение «внутрь» идёт через убывающую функцию Коши, а «наружу» — через Хьюбера.
5. **Оценка:** итерационный EKF (Гаусс–Ньютон на апостериорном максимуме, IRLS), затем сглаживатель Рауха–Тунга–Штрибеля.
6. **Перед или зад:** рамка их не различает, ящик симметричен, и ошибка выбора стоит 22 м. Различает движение: машина едет передом. Устойчивая отрицательная скорость (≥ 0,3 с) разворачивает всю историю трека на пол-оборота с пересчётом ковариаций через якобиан.
7. **Сопоставление:** пятна у прогнозной рамки собираются жадно, пятно входит, если увеличивает IoU. Так силуэт, разрезанный деревом, склеивается, а лист рядом или «призрак» стоящей фуры — нет. Пятно, которое в основном вне окна, отбрасывается. Частичный силуэт внутри прогноза (фура за холмом) принимается.
8. **Подтверждение и перезахват:** новая гипотеза пробная, пока ≥ 2 камеры не подтвердят её 4 раза за 8 кадров. Если у трека опора меньше двух камер, цель ищется заново по всем пятнам.
9. **Итерационное сглаживание (офлайн):** пятна сопоставляются со сглаженной траекторией прошлой итерации, она уже учла всю запись. Итерации идут до сходимости, с нижней релаксацией 0,5.

### Фон и пятна

- **Статичная камера:** медиана по выборке кадров записи (офлайн) или гауссиана на пиксель (живой режим). Порог в сигмах фона: качающаяся листва сама поднимает себе порог.
- **Поворотная камера с известной позой (cam-5):** фон хранится как функция направления луча в мире, d = Rᵀ K⁻¹ [u, v, 1]ᵀ, в сферической панораме. Для вращения вокруг центра это точное соответствие при любой глубине, без оценки движения по картинке.
- **Экспозиция:** перед сравнением фон умножается на медиану отношения кадр/фон по каждому каналу.
- **Тень:** на текстурном фоне (снег) тень сохраняет его рисунок, локальная корреляция ≥ 0,5 при однородном затемнении окна. Гладкий борт фуры рисунок закрывает, корреляция ≈ 0. Где фон гладкий, остаётся признак «потемнело, цветность прежняя».
- **Два прохода:** второй раз медиана строится без пикселей фуры по треку первого прохода. Камера, сопровождающая цель, иначе «впитывает» её в фон.

## Альтернативы: что пробовали и что показали замеры

| Идея | Результат | Решение |
|---|---|---|
| Триангуляция центров пятен (было) | 3D на 9 % кадров: центры силуэта длинной фуры из разных ракурсов — разные точки корпуса | заменено подгонкой ящика |
| Курс = касательная к траектории опорной точки | невязка 10,5 px против 7,6 px у трактрисы | задняя ось как опора |
| Ящик без тангажа | на холме (уклон до 17°) опорная точка «ныряет» на 4 м | тангаж в состоянии |
| Свободный тангаж (случайное блуждание) | при одной камере ящик «проваливается» сквозь землю, Z до −14 м | процесс О–У |
| Симметричная функция Хьюбера | RMSE 8,6 м против 5,7 м у асимметричной | Коши «внутрь» |
| χ²-гейтинг камер | RMSE 11,8 м: ковариация фильтра пока оптимистична | отложено |
| Онлайн-фон в контрольном прогоне | далёкая медленная фура «впитывается» в фон | медиана записи |
| Тень по сдвигу в синий (свет неба) | у пикселей фуры тот же сдвиг (+0,02…+0,07) — признак не разделяет | отвергнуто замером |
| Тень по корреляции текстуры | фура ≈ 0, тень 0,78–0,91 (cam-5) | принято |
| Один проход фильтр + RTS | RMSE 7,3 м, максимум 48 м | итерационное сглаживание |
| Итерации без релаксации | колебания, RMSE 3,4 м | релаксация 0,5 → 3,1 м |
| Перезахват внутри итераций | дыры направляющей → ложный перезахват → 50 м в конце | перезахват только в живом режиме |

Отложено с причиной:
- Нейросеть RGB → тепловизор (цвет «температуры» выдуман) и YOLO на каждый кадр: тяжело, а у модуля `object_detector.py` тот же интерфейс детектора.
- Калибровка плоского поля (виньетирование) поворотной камеры: она даёт полосы на панорамном фоне cam-5 — это следующий шаг точности.

## Как добавить камеру

Тот же `Session.add_source`, меню «Добавить видео» или телефон по кабелю. Нужна поза в `session.poses`: лист ChArUco или таблица Way1. Подгонка ящика работает на любом числе камер: каждая добавляет четыре стороны рамки в одну систему уравнений.

## Ступени ухудшения условий

0. Одна цель, камеры стоят, позы известны.
1. Помеха на кадре (второе движение, листва) — порог в сигмах фона, сопоставление с прогнозом ящика.
2. Окклюзия деревом или склоном на части камер — функция Коши «внутрь», частичный силуэт внутри прогноза.
3. Цель видит одна камера — дальность по размеру ящика и модель движения; ошибка растёт до ~4–5 м.
4. Крутящаяся камера — фон в панораме направлений по позе кадра.
5. Телефоны, рассинхрон — тот же шаг сессии, точка при ≥ 2 камерах.

## Фишки, которые сохраняем

Телефоны по кабелю, поле 3D со следом, конусами камер и 3D-ящиком, прогноз траектории, контрольный прогон с отчётом по кадрам.
